# PDCA運用ルール

更新日: 2026-10-07

## 目的
予測ロジックの改善を短時間で継続し、未解決事項を放置せず、翌日のPDCAへ正確に引き継ぐ。

## 1. 毎回のPDCA終了条件
各テーマは必ず次のいずれかまで到達して終了する。
- 採用: 本番反映に十分な根拠あり
- 却下: 改善なし、または副作用が大きい
- 継続検証: 未解決だが、原因仮説・次の検証方法・判断基準まで決定済み

「原因不明のまま保留」「次回また考える」では終了しない。

## 2. 検証ルール
- 配点変更 = 全対象レースで全体検証
- 内部条件・補正変更 = 影響対象を重点検証し、最後に全体副作用確認
- 本番ロジックは検証途中で変更しない
- 主要評価: 1着、勝者TOP2、勝者TOP3、TOP3完全一致、着順一致、勝者平均予測順位、回収率、日別安定性
- x→o / o→x は原因診断用であり、配点変更の主判定には使わない

## 3. 時間管理
1テーマを長時間追い続けない。
1) 仮説
2) 最小検証
3) 改善傾向あり → 対象拡大
4) 改善傾向なし → 却下または別仮説
の順で進める。
外部取得障害などで停滞した場合は、同じ方法の再試行を繰り返さず代替経路を決める。

## 4. 毎日の議事録
PDCA終了時に日付単位で以下を保存する。
- 今日検証したテーマ
- 現行仕様
- 仮説
- 使用データ・対象レース数
- 比較結果
- 採用 / 却下 / 継続検証
- 判断理由
- 本番変更の有無
- 発見した問題
- 解決策
- 翌日へ繰り越す項目
- 翌日の最初の作業
- 採用判断基準

## 5. 翌日への繰り越し
繰り越し項目には必ず
「何が未完了か」「なぜ未完了か」「次に何をするか」「どの結果なら採用/却下するか」
を記録する。
