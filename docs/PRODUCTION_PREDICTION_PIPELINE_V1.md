# 予測パイプライン本番仕様（検証ブランチ：2026-10-09）

## 単一データフロー

1. 朝の番組・履歴を収集して朝スコアを計算・保存
2. 直前の公式展示・気象・コース情報を収集・保存
3. 朝スコアと直前収集値をもとに通常の直前6艇スコアを算出
4. **その同じ直前6艇スコア**で風神・雷神を判定
5. どちらかが発動したときだけ専用AI補正を6艇に適用し、3連単120通りを評価し上位24通りを保存
6. 1レースIDの予測・判定・買い目を `predictions/YYYY/MM/DD/live/formation_predictions_final_YYYYMMDD.json` の `races[]` にまとめる
7. 「最新情報」と「レース照合」は同じ予測レコードを読み、結果ページではこの保存予測に**後から結果・払戻だけ**を結合する

**新しい予測記録の二重保管はしない。** 締切順の `predictions/latest_by_deadline.json` はこの正本から生成する表示用派生物。履歴用元データと配当情報は正本と別のため、結果を予測計算へ渡さない。

## 数値ロジックの独立設定

| 種別 | 設定ファイル | 呼出し元 |
|---|---|---|
| 朝 | `config/logic/morning.json` | `collectors/build_morning_prediction.py` |
| 通常直前 | `config/logic/live.json` | `collectors/build_live_prediction.py` |
| 風神雷神判定・専用24点選択 | `config/logic/fujin_raijin.json` | `collectors/build_latest_prediction_view.py` |

設定は `collectors/logic_registry.py` が必須項目、配点合計、購入点数を検査する。設定が見つからない／壊れた場合に勝手に別ロジックへ戻さない。

風神雷神の16分類別の個別補正表は**既存の** `config/signal_ai/signal_ai_corrections_v1_20261008.json` を引き続き参照する。通常AIスコア買い目ロジックは**従来どおり** `config/ai_score/` に独立保存。上記３種と混同しない。

- 朝の本番：40/20/20/5/15、内部要素40/20/30/10、モーター40/60、ボート50/50、級別1/0.75/0.45/0.25
- 直前の本番：構造80・展示タイム6・展示ST14、展示F評価0.4、本人ST平均との差の係数は現行維持
- 雷神：直前順位4位以下、上昇7.5点以上、Lv2=10点以上、Lv3=対象スコア50点以上
- 風神：1位低下5点／TOP3合計低下10点／1位低下3点かつ1・2位差5点以内
- 専用AI：補正後6艇、買い目評価=1着0.50＋2着0.30＋3着0.20、購入24点×100円

## 表示および保存整合性

- シグナルレベルは一度計算して保存し、画面表示時に再計算しない。
- **F1R0〜F3R3などが発動し専用AI24点が無い場合、通常AI8点へ代替しない。** 「修復対象」と表示して正確な未評価件数を残す。
- F0R0では専用AIは対象外。通常AIスコア予測は別会計。
- 補完された公式展示は事後の検証入力として扱えるが、結果・払戻・実着を予測処理には渡さない。過去の当時の購入記録を勝手に書き換えない。
- `logic_identity` にモデル名、設定パス、設定SHA256、適用日を保存し、日々のPDCAでロジックが変わってもどの設定で計算したか追跡する。
- レース照合・結果成績・AI分析の集計は同一レースIDと同一の発動判定で突合する。母数の差・未評価数は隠さない。

## 運用・リリース条件

1. `main` に直接大規模変更せず検証ブランチで各モデルの配点同値テストと画面結合テストを行う。
2. `python -m unittest discover -s tests -p test_logic_pipeline_contract.py -v` に合格する。
3. `build_deadline_prediction_view.py --date YYYYMMDD`、`build_family_prediction_page.py`、`build_family_race_compare_page.py` の同日データ統合テストに合格する。
4. 本番の最新情報→レース照合→結果成績→AI分析で、シグナル発動数・評価可能数・専用AI24点の損益が一致することを確認し、必要な場合のみ本番へマージする。
5. 新ロジックは**新しい版として登録**し、後から旧版の保存値を暗黙に上書きしない。数値を調整するときは設定ファイルとモデルバージョンだけを更新し、画面コードを書き換えない。

※ 直前データ収集の成功率はこの表示／計算リファクタリングだけでは保証されない。収集監視・再取得・実績検証は独立に確認しなければならない。
