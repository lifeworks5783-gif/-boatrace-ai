# 共通予測パイプライン・製品版移行設計（2026-10-09）

## 正本と処理順

1. **朝入力 → 朝AIロジック → 朝予測**（朝スコア・全艇・ロジック版・入力取得時刻を保存）。
2. **公式直前入力を収集／再収集 → 直前AIロジック → 直前予測**（展示情報、直前順位、朝差分）。
3. **確定した通常直前スコア → 風神・雷神発動判定**（F0〜3、R0〜3）。シグナル判定は1回だけ。
4. **発動時のみ、専用補正設定を適用 → 6艇再評価 → 3連単120通り → 上位24買い目を確定**。
5. **canonical/race_predictions_YYYYMMDD.json** に同じrace_idの朝・直前・シグナル・買い目の参照とスナップショットを保存。結果・払戻は含めない。
6. **最新情報とレース照合は両方とも共通データを読む**。レース照合だけが結果と払戻を後から紐付け、各方式を別会計で清算する。

旧予測 JSON/CSV は削除せず、新たな canonical は派生の読み込み用正本とする。現行過去値を勝手に上書きしない。

## バージョン変更の手順（必須）

- **既存の v1.json を直接書き換えない**。v2.json を作り、設定検証、数値回帰、過去日データで対照比較してから有効化する。
- 朝・直前・風神雷神・購入ルールをそれぞれ独立に改定する。変更しない設定版は固定。
- 保存済みの予測は生成時の `model_id`、設定ファイル、SHA-256、入力ソース・時刻に紐付け、旧予測を新ロジックで再計算した場合は別版として保存する。結果判明後の再構成を「当時購入済み」とは表示しない。
- **過去の予測と新設定によるバックテストは別系列**。パフォーマンスを混ぜない。
- 結果や払戻を予測入力へ混入させない。結果取得後は清算と検証のみ。

## データの欠落・復元

- 直前の公式データ取得が失敗した場合、朝補完値を直前の確定観測として保存しない。取得の再試行・過去公式beforeinfo・保存済みスナップショット等、複数経路を追う。
- 本来の展示入力を復元できたら、同一モデル版と凍結済みの予測材料で直前スコア→シグナル→専用買い目を再構築する。結果・配当は**一切参照しない**。
- 復旧したものは `signal_ai_replay` と provenance を明示。予測時点の買い目か、事後再現かは厳密に区別する。
- シグナル発動なのに24点が不足したときは `signal_ai_unresolved`。通常AI8点の不的中に切り替えない。集計上は未評価件数を別計上する。
- 日付・会場・Rの複合IDで結合。画面ごとの独立判定を禁止。
